# Known limitations

- The workspace source is branded Afraz Kolkata and includes a curated discovery directory (20 places, 20 food listings, 10 shopping areas, and 5 bus-route listings), searchable category screens, attributed catalog images, source-backed place detail sections, metro lines, nearby-area links, local favorites, persistent theme choice, bottom tabs, Google Maps links, and an in-memory multi-stop planner with reorder/remove/share actions. The directory is a starting point, not an exhaustive catalogue of Kolkata. The next Android build is version 1.2.1, version code 3; do not describe it as released until the APK build has completed.
- Food and place listings are discovery leads with source labels. Verified costs/hours are available only for the named venue pages documented in `DATA_SOURCES.md`. The app does not include current reviews, menus, dish-level prices, food-safety reviews, or live availability. Those fields are not filled with guesses.
- No Supabase project or Google Places/Routes credentials were supplied. Live provider data, user accounts, saved itineraries, admin publishing, route planning, in-app maps, and live imagery require project setup and are not active. Favorites and theme preference are saved locally; itinerary stops currently remain screen state and are lost when the app restarts.
- The previous EAS APK was signed with the project’s remote Android keystore and is suitable for direct installation/testing. Keep the EAS credential private and verify signing ownership before publishing through a store.
- Older ABI-specific APKs are still present as `dist/KolkataExplorer-arm64.apk` and `dist/KolkataExplorer-x86_64.apk`; they predate the current source. Use `dist/AfrazKolkata.apk`, which contains arm64-v8a, armeabi-v7a, x86, and x86_64 (minimum API 24, target API 36).
- The app does not yet query the editorial places table or provide live Places text search or map tiles. Catalog photos are attributed remote image URLs; they require network access. Generic category photos are labeled as illustrations rather than venue imagery.
- Shopping tables and documentation are present, but category recommendations, current comparable prices, reviews/moderation, and admin workflows remain planned work.
- Bus and transit data requires official/licensed source verification. No live vehicle feed, verified bus schedule, or fare database is included.
- The Nov 4 EAS failure was traced to generated `android/build/generated/autolinking/autolinking.json` containing absolute Windows package paths. Linux Gradle treated those as relative project paths. Root ignore rules now exclude Android build output, native caches, and `.git` from EAS archives; archive inspection confirmed the stale autolinking file is absent.
- On 7 Nov 2026, EAS preview build `917021b8-125e-4065-954f-fe08319a4386` completed successfully for source commit `1cfe9265b891040c3320e13663086e5f15ed43eb` (app version 1.2.0, Android version code 2). The downloaded APK passed `aapt` metadata validation and `apksigner` v2 signature verification. Local ESLint, TypeScript checking, and all 5 tests passed. The earlier corrected build `4544a92a-70a6-42b2-8f28-ae4b5c59801a` also completed successfully.
- Expo Doctor reported non-blocking project hygiene issues: `eas-cli` is listed as a project dependency, `expo-constants` should be declared directly for `expo-router`, native folders mean some `app.json` settings will not sync, and several installed Expo/TypeScript package versions differ from the SDK's preferred versions. The APK build itself completed; resolve these items before the next planned dependency upgrade.
