# Known limitations

- The workspace source is branded Afraz Kolkata and includes a curated discovery directory (20 places, 20 food listings, 10 shopping areas, and 5 bus-route listings), searchable category screens, listing details, Google Maps links, and an in-memory multi-stop planner with reorder/remove/share actions. The directory is a starting point, not an exhaustive catalogue of Kolkata. The current universal multi-ABI APK is `dist/AfrazKolkata.apk` (Android package `com.afraz.kolkataexplorer`, version 0.1.0).
- Food and place listings are discovery leads with source labels. The app does not include verified current prices, opening hours, ratings, menus, dish-level prices, food-safety reviews, or live availability. Those fields are not filled with guesses.
- No Supabase project or Google Places/Routes credentials were supplied. Live provider data, reviews, authentication, saved places/itineraries, admin publishing, routing, in-app maps, and imagery require project setup and are not active in this APK. The planner currently lives only in screen state and is lost when the app restarts.
- The current EAS APK was signed with the project’s remote Android keystore and is suitable for direct installation/testing. Keep the EAS credential private and verify signing ownership before publishing through a store.
- Older ABI-specific APKs are still present as `dist/KolkataExplorer-arm64.apk` and `dist/KolkataExplorer-x86_64.apk`; they predate the current source. Use `dist/AfrazKolkata.apk`, which contains arm64-v8a, armeabi-v7a, x86, and x86_64 (minimum API 24, target API 36).
- The app does not yet query the editorial places table or provide live Places text search, map tiles, and photos.
- Shopping tables and documentation are present, but category recommendations, current comparable prices, reviews/moderation, and admin workflows remain planned work.
- Bus and transit data requires official/licensed source verification. No live vehicle feed, verified bus schedule, or fare database is included.
- The Nov 4 EAS failure was traced to generated `android/build/generated/autolinking/autolinking.json` containing absolute Windows package paths. Linux Gradle treated those as relative project paths. Root ignore rules now exclude Android build output, native caches, and `.git` from EAS archives; archive inspection confirmed the stale autolinking file is absent.
- On 7 Nov 2026, the corrected EAS preview build `4544a92a-70a6-42b2-8f28-ae4b5c59801a` completed successfully (566 Gradle tasks). The downloaded universal APK passed `aapt` metadata validation. Local lint, TypeScript checking, all 5 tests, and `git diff --check` passed.
- Expo Doctor reported non-blocking project hygiene issues: `eas-cli` is listed as a project dependency, `expo-constants` should be declared directly for `expo-router`, native folders mean some `app.json` settings will not sync, and several installed Expo/TypeScript package versions differ from the SDK's preferred versions. The APK build itself completed; resolve these items before the next planned dependency upgrade.
